# 2025–26 shift reconstruction audit

Snapshot: **2026-09-23 12:31:39.878310 UTC**. Method:
`nhl-on-ice-v1`. [Machine-readable results](20252026-shifts.json),
[performance and query plans](20252026-profile.json),
[input manifest](20252026-inputs.json).

This audit supports a conservative subset for future sequence analysis. It does
not justify treating every timestamp as a known lineup. **279,713 events
(63.24%)** have a structurally resolved identity set and matching situation
counts; **271,212 (61.32%)** also have no interval-source warnings. Count
compatibility alone is much broader and must not be mistaken for identity
accuracy.

available in game diagnostics.

Of **53,122 comparable player-games, 99.7214% match exactly**. Median and p95
absolute difference are zero; mean absolute difference is 0.05096 seconds.
All comparable nonzero differences in this snapshot are positive, with a maximum
of 324 seconds. Null/invalid/partial comparisons are excluded from that
distribution rather than silently treated as zero.

The largest discrepancy is goalie 8483710 in game 2025020634: interval union
2,400 seconds, source-duration sum 2,359 seconds, official TOI 2,076 seconds.

unresolved source discrepancies; no duration field was chosen to force a match.

Stored decoded columns agree with raw situation codes throughout. Counts match
or fit bounds for **99.8901%** of events, but **36.55% of all events only have
boundary-compatible counts**. A compatible count does not tell us which player
changed first. Conversely, 437 structurally incomplete events have exact
remaining counts; that does not erase the missing/excluded source evidence.

The [method document](../on-ice-reconstruction.md) defines the two independent
status axes and the conservative subset. In particular, a `resolved` status
can disagree with the NHL situation code and must not be used alone.

## Mismatch investigation

Contexts below overlap. They describe observed circumstances, not proven causes.

| Context | All events in context | Count mismatches |
| --- | ---: | ---: |
| Period/game boundary | 15,099 | 314 |
| Coincident shift boundary | 162,030 | 374 |
| Regular-season OT | 4,739 | 268 |
| Playoff OT | 1,518 | 30 |
| Goalie absence expected by situation code | 13,501 | 358 |
| Penalty-shot-like count pattern | 40 | 40 |
| Source interval warnings | 14,891 | 119 |
| Delayed-penalty event | 3,643 | 2 |

Major unresolved categories:

1. **Terminal and period-boundary semantics.** Sudden-death OT terminal events
   frequently publish a four-skater/no-goalie tuple while intervals represent
   the preceding three-skater/goalie lineup. For example, game 2025020008 at
   OT 02:12 has differing terminal observations. The audit retains the
   disagreement; neither a neighboring event nor the event type overwrites it.
2. **Clock-stopped penalty shots.** Forty events have one-shooter/one-goalie
   count patterns. A sampled HTML report confirms a penalty shot for
   2025020077, period 3 at 02:23 (JSON event 112). Continuous shifts describe
   surrounding manpower and cannot reconstruct that setup. This remains an
   explicit limitation, not an interval fix.
3. **Source identity/timing defects.** Foreign-team contamination, duplicate
   intervals, excess players and TOI discrepancies require source investigation.
   The HTML sample finds six mismatching player sets in game 2025020036 late in
   period 3, plus one at an earlier penalty. Count agreement can miss an identity
   defect.
4. **Situation-code defects or differing event conventions.** In 2025020011,
   three events around period 1 14:02–14:33 have lower skater counts in the JSON
   situation code than the shifts imply. The HTML player lists agree with the
   reconstructed sets. A count mismatch alone is not proof that shifts are wrong.
5. **Goalie pulls and delayed penalties.** Many expected empty-net states do
   agree. The remaining mismatches need event-specific investigation; the engine
   does not infer a pull merely to satisfy a code or propagate a delayed-penalty
   explanation to nearby events.

## Independent HTML identity sample

Six games were selected deliberately: a baseline regular-season game, OT,
count-disagreement and interval-anomaly examples, a penalty shot, and a playoff
game. This is **not a random sample or a season accuracy estimate**. The HTML
report is a separate NHL presentation and can share upstream errors.

The helper matches only unique period/time/type keys, then compares NHL player
IDs and goalie roles using the game roster. It does not align on unrelated

## Reproduce and profile

Use the commands in the [method document](../on-ice-reconstruction.md).
The 484 MiB source snapshot and cached HTML/PBP inputs are retained locally
under `data/audits/20252026/` (gitignored), not committed. The input manifest
records the source file's SHA-256 and size; the summary records every game's
analysis-input hash. A database-backed rerun may differ after source refreshes.
The saved snapshot permits exact analytic replay without the database.

```sh
./target/release/pucksdata shifts audit --season 20252026   --input data/audits/20252026/source.jsonl   --output replay.json --games-out replay-games.jsonl --events-out replay-events.jsonl

python3 scripts/check_on_ice_html.py --events replay-events.jsonl   --report data/audits/20252026/html/2025020077.html   --pbp data/audits/20252026/html/2025020077.json --output replay-html.json
```

Source hash and all analytic counts are reproducible; generation time,
performance fields and live-only query plans naturally differ. The final
offline replay refined penalty-shot context and source-coverage reason labels after the live pass; source
hash, TOI totals, reconstruction totals and count-agreement totals were checked
unchanged. The profile artifact records both passes.

The first-batch PostgreSQL plans used `shifts_pkey`, `idx_events_game_id` and
the official game-table primary keys. Their measured execution times were
426.85 ms, 394.28 ms and 17.06 ms respectively; the small identity/player
dimension tables were hash-joined. These are observed first-batch plans, not
claims about every season or server.

The evidence does not justify a permanent event-player bridge or another index.
Season analysis is inexpensive relative to database transfer; bounded reads and
offline replay already handle the measured scale. No canonical tables, source
rows or production schema were changed by this audit.
